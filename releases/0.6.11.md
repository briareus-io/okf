# OKF CLI and plugin 0.6.11

Save a recurring chain of relationship reads in a bundle manifest, then run it by name with
`okf query`. Both `query` and `show` can now return a Markdown subsection by its heading path.

## Save and run a query

Define a query under `settings.saved_queries` in the primary bundle. Start from a concept ID
or a named list/search preset. Each hop can follow outgoing links or incoming backlinks,
filter typed relationship occurrences and their attributes, and narrow the concepts it reaches.
CLI filters, sorting, and pagination apply to the final distinct endpoints. Select properties
with `--project`, or request bodies, outlines, or sections.

A saved query can span registered bundles. For example, given the product manifest in the
[multi-bundle guide](https://github.com/briareus-io/okf/blob/v0.6.11/knowledge/guides/work-with-multiple-bundles.md#run-a-saved-query-across-bundles):

```sh
okf query referenced-policies notes/overview --bundle-id demo.product --scope-bundle demo.policy --json
```

The product bundle supplies the definition and starting concept. The policy bundle supplies
the target. Results preserve bundle, concept ID, and version. An authored reference alone
does not expand examination scope.

## Read one section

Pass a JSON array of heading titles from outermost to innermost. The result includes the
matched heading and its descendants up to the next sibling or higher-level heading.

```sh
okf show notes/triage product --section '["Operations","Recovery"]'
```

A saved query continues past missing or ambiguous headings in individual concepts and reports
the affected delivery. JSON includes a section record with line bounds for each successful read.

## Performance and completeness

A local working-tree query starting at a known concept can follow an outgoing-only chain on
demand. Parsed documents and missing IDs are reused within the invocation. Preset starts,
incoming hops, explicit scope, and historical reads use the scoped executor. On a warm-cache
5,000-document fixture, a two-hop saved query took 6.1 ms median versus 89.9 ms with the
scoped implementation before optimization. These are local release-build measurements.

Inspect the `saved-query-summary` strategy, stage counts, unresolved endpoints, and examination,
matching, and delivery evidence. A complete outbound read can leave unrelated documents
unexamined. Use bundle validation to assess the health of the entire bundle.

## Guides and skills

The [saved-query guide](https://github.com/briareus-io/okf/blob/v0.6.11/knowledge/guides/save-and-run-queries.md)
includes an ontology, sample concepts, mixed-direction chains, and expected results. Task guides
now separate example files from individual commands and their outputs. Updated skill guidance
covers choosing a saved query, selecting cross-bundle scope, and interpreting partial results.
The feedback skill and standalone draft template now prompt authors to review a fictional
scenario from the perspective of a maintainer who has never seen the session.

## Upgrade

Install the 0.6.11 CLI before using `query` or `show --section`. Existing bundles need no
migration, and existing query presets retain their single-operation filter semantics. Upgrade
all readers of a shared manifest before introducing `settings.saved_queries`: older CLIs can
reject the unknown setting even when running another command. The plugin retains its general
stable CLI range of `>=0.6.8, <0.7.0`. On older compatible CLIs, use individual links/backlinks
and outline/line reads. The OKF document specification remains v0.2.
