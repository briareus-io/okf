# OKF CLI and plugin 0.6.3

## Context delivery

- Text context explains selection, inspection roles, summary omissions, origins, and exact expansion
  commands. Empty unavailable/settings fields are hidden; the footer distinguishes required delivery
  from discovery summaries.
- `bundle context --settings-detail compact` explicitly projects relevant settings in either output
  format. Full JSON settings remain the default. Operational defaults are retained, omitted values
  are identified, and selected workflows/unknown dependencies conservatively retain all groups.
- `--stats` reports delivered instruction bytes per section and totals. `--guidance-budget N` adds
  an advisory mandatory-instruction budget without truncation or failure.
- Rules can opt into `tier: reference` and expand with `--rule ID`. Existing rules default to
  `mandatory`. Expanded references remain inspected material. The existing `--all` inspection
  semantics are preserved; target/type/trust selectors remain deferred.
- Global guidance, rules and workflows accept optional `provenance` publisher metadata, returned in
  `origin.provenance`. Authored comments remain intact; publishers can stop inserting boilerplate.

## Optional freshness receipts

`bundle context --token` emits one stateless token per examined bundle after instruction delivery.
Pass the returned token string using `--context TOKEN` or `--context @FILE` on supported commands;
repeat for explicitly scoped bundles. `bundle context --check-token TOKEN` checks without replaying
instructions, and optional `--operation` arguments check coverage. Tokens bind resolved bundle roots,
identity/snapshot, the loaded selection, effective settings and ontology, loaded instruction files,
and selected workflow resources. An ordinary concept edit does not invalidate them.

A supplied stale, wrong-bundle or uncovered token refuses execution before mutation. Commands
without tokens retain their existing behavior: this release does not require context tokens for
ordinary CLI use. Inspection-only context and workflows missing required inputs cannot issue an
execution token. A token is neither a credential nor proof of comprehension. It does not bind
concept contents, command arguments, or prevent subsequent external changes; existing write guards,
review, and validation remain necessary.

Context digest version is now 2: selected workflow resource bytes affect the digest. Discard cached
version-1 context and reload. The operation stream version is unchanged; new records are additive.

## Changeset support-resource fix

Changeset final-state conformance now uses the bundle tooling profile: root `.okf-bundle/*.md`
resources are not treated as concepts. Guarded no-op plans and coordinated writes work in bundles
with manifest-referenced plain Markdown instructions. Support files remain in the reviewed baseline;
changing them still invalidates `--expect`. Ordinary and nested Markdown still require conformance.

## Skills and compatibility

The shared protocol batches initial context requests, uses receipts before planned mutations,
clarifies reuse and reload triggers, and distinguishes mandatory guidance from reference stubs.
Initialization includes concise-guidance authoring examples; update includes a small-prose-edit
path. Multi-bundle examples now load context for the operations they demonstrate.

CLI and both plugins are 0.6.3. The plugin supports stable CLI versions `>=0.6.3, <0.7.0`.
Manifest version remains 1 and existing manifests remain valid. Older CLIs reject the new optional
manifest fields, so upgrade before authoring them. OKF document format remains v0.2.
