# OKF CLI and plugin 0.6.0

OKF 0.6.0 makes bundles carry their own settings and agent guidance, adds relationship query
presets and logical references, and introduces reviewed Git dependency acquisition with accepted
locks. The repository's knowledge bundle now uses these capabilities as an executable showcase.

## Upgrade and compatibility

- Install matching CLI and plugin versions. The plugin supports stable CLI versions
  `>=0.6.0, <0.7.0`; the Rust workspace, lockfile, and both plugin manifests are versioned 0.6.0.
- Core OKF remains v0.2. Manifest v1, catalog v2, and lock v1 are separately versioned tooling
  formats. Existing directory-only catalog v1 files and supported legacy TOML remain readable.
- Root `.okf-bundle/` is support material under the bundle tooling profile. Use
  `okf bundle validate` for manifest checks and `okf validate --profile bundle` for knowledge
  documents. Default/core validation retains the physical Markdown boundary used by older readers.
- JSON consumers must read record kinds and completion evidence rather than assume every payload
  is a concept. New records include guidance, workflow/context, effective filters, snapshot evidence,
  validation profiles, and migration/update reports.
- TOML migration is explicit: doctor produces a reviewable plan, then applies the selected plan
  with conflict checks, path rebasing, preserved originals, and recovery information.

Read the [0.6 migration guide](https://github.com/briareus-io/okf/blob/v0.6.0/knowledge/reference/migrations/0.6.0.md)
and [configuration reference](https://github.com/briareus-io/okf/blob/v0.6.0/knowledge/reference/configuration.md)
before changing automation.

## Portable bundle configuration and guidance

- Optional `okf-bundle.yaml` owns descriptions, lint/query/view settings, write policy, explicit
  presets, guidance, and named workflows. `ontology.yaml` stays separate. The catalog owns workspace
  identities, locations, and default selection.
- Guidance can be global or selected by canonical CLI command paths, including subcommands.
  Inline `instructions` and required `instructions_file` support longer authoring/serving procedures.
- `bundle context` exposes effective settings and origins, complete selected guidance, workflow
  inputs/defaults, and an effective digest that includes loaded instruction files. Scoped context
  retains each bundle's identity; `--all` and historical reads remain inspection, not activation.
- `.okf-bundle/` can hold instructions, scripts, templates, reports, and evaluation material.
  Knowledge discovery hides it; explicit resource reads expose it without execution. Snapshots
  preserve support files, and read-only policy applies to them.
- All ten skills use one shared compatibility/context protocol before substantive work. The skill
  audit removed contradictory validation, source-health, migration, and reference-handling guidance.

See the [runnable customization guide](https://github.com/briareus-io/okf/blob/v0.6.0/knowledge/guides/customize-a-bundle.md)
and [manifest design](https://github.com/briareus-io/okf/blob/v0.6.0/knowledge/contributing/design/bundle-manifest.md).

## Relationship queries and source evidence

- `links` and `backlinks` filter authored kinds, inverse labels, relationship rules, related types,
  edge attributes, and related metadata. Conditions stay correlated to one occurrence before
  deduplication and pagination; scan budgets bound document parsing and report incomplete results.
- Named presets are explicitly selected. Graph predicates filter traversal; expansion predicates
  filter expanded edges without silently changing primary hits. Integrity checks do not inherit
  narrowing query presets.
- `okf://<bundle-id>/<path>` references work in Markdown, declared metadata, and source resources.
  They use the selected catalog and accepted lock, without implicit acquisition. Ordinary relative
  paths and HTTPS references retain their meaning.
- `bundle-resource` fingerprints distinguish content changes from source/revision identity changes.
  Source snapshot expectations remain separate from the accepted dependency lock.
- Workspace and per-bundle historical selectors reopen available immutable evidence, including
  concepts, ontology, manifests, and support resources, without fetching missing objects.

See the [blocking-defects recipe](https://github.com/briareus-io/okf/blob/v0.6.0/knowledge/guides/find-and-read-knowledge.md#find-defects-blocking-a-feature)
and [source/provenance concepts](https://github.com/briareus-io/okf/blob/v0.6.0/knowledge/concepts/sources-and-provenance.md).

## Managed Git dependencies

- Catalog v2 supports read-only Git registrations and a committed `okf-catalog.lock`. One accepted
  revision per repository is supported in a catalog; related bundle subpaths share an update unit.
- `catalog update` plans an exact candidate. Explicit `--apply` accepts the reviewed commit without
  re-resolving a moving ref and rejects stale catalog, lock, or examined-consumer baselines.
- Update reports compare concepts, ontology, manifest/instruction/script changes, scoped links,
  and before/after lint. Incomplete impact is explicit; its override cannot waive compatibility,
  integrity, or stale-plan failures. JSON preserves `plan_kind` separately from the record kind.
- `catalog sync` materializes accepted revisions. `--check` verifies local correspondence offline;
  `--rebuild` quarantines corruption and reconstructs from available objects. OS-held coordination
  locks release on process exit.
- Immutable snapshots are shared through a per-user cache with a local cache-path override. Local
  checkout overrides preserve commit/content expectations and access policy. Existing Git credentials
  supply authentication; credentials are not stored in bundle configuration.
- Managed OKF mutation paths refuse upstream writes, including explicit cache paths and support
  files. Acquisition does not execute upstream hooks, content filters, workflows, or scripts.

See [consume remote bundles](https://github.com/briareus-io/okf/blob/v0.6.0/knowledge/guides/remote-dependencies.md)
and the [remote design](https://github.com/briareus-io/okf/blob/v0.6.0/knowledge/contributing/design/remote-bundles.md).

## Corrections and executable documentation

- Fixed catalog interpretation of repository-relative Git Markdown sources: they remain resource
  dependencies without becoming invented concept links unless explicitly mapped.
- Existing index/log, artifact, and support references resolve without false missing-concept findings.
  Logical relationship records now agree with their enclosing catalog edge's target and status.
- Historical remote queries retain bundle subpaths and cannot expose sibling-bundle concepts under
  the selected identity. Impact reports honor consumer checkout overrides.
- Required instruction files are checked as readable UTF-8. Hidden support directories are pruned
  before ordinary knowledge traversal. Protected output paths include migration-plan files.
- Reworked the designs as coherent specifications, improved task-based navigation, and added runnable
  view/lint/preset/workflow examples. The live `okf.docs` showcase preserves its lint policy and views,
  adds useful presets and file-backed workflow context, and checks behavior rather than page counts.

The [live-bundle tour](https://github.com/briareus-io/okf/blob/v0.6.0/knowledge/guides/tour-the-bundle.md)
contains the capability-coverage map. Validation covers the Rust suites, executable skill workflows,
worked documentation examples, generated-reference drift, release metadata, and installer behavior.

## Boundaries

- Live pointers are a modeling convention plus guidance, not a built-in fetching/freshness engine
  ([#4](https://github.com/briareus-io/okf/issues/4)). Observed facts still need source evidence.
- Bundle-local metadata and workflows address much of [#5](https://github.com/briareus-io/okf/issues/5),
  but an LLM evaluation runner and standardized persistent registry semantics remain separate work.
- [#7](https://github.com/briareus-io/okf/issues/7)'s dependency lifecycle is implemented with deliberate
  refinements: plan before apply, per-user cache, explicit version sets, and separate online/offline
  checks. Read-only enforcement covers OKF writes; arbitrary shell tools require filesystem isolation.
- Submodule/LFS hydration, writable Git registrations, multiple accepted revisions of one repository
  in one catalog, generic logical-link export, and automatic script execution are not included.
- The footnote false-positive fix from 0.5.2 remains covered by regression tests
  ([#6](https://github.com/briareus-io/okf/issues/6)); it is not a new fix in 0.6.0.

Release assets include CLI archives for macOS and Linux on ARM64 and x86_64, `SHA256SUMS`, and the
standalone `install.sh`. The release workflow signs/notarizes macOS binaries and checks native
builds before publishing the complete asset set.
