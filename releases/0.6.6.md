# OKF CLI and plugin 0.6.6

OKF 0.6.6 adds recovery-safe current bundle selection and completes logical-reference
preflight support for scoped ontology-gated changesets. Selection can be retained across
calls without loading bundle content, including when a pending transaction prevents
ordinary reads and guidance delivery.

## Upgrade and compatibility

Install CLI and plugin 0.6.6 together. The plugin requires stable CLI versions
`>=0.6.6, <0.7.0`; older binaries do not support selection receipts. The workspace and both
plugin manifests are 0.6.6. The OKF document format remains v0.2; manifest v1, catalog v2,
and lock v1 are unchanged. Existing path and catalog selectors remain supported.

Review the [0.6.5 notes](0.6.5.md) for scoped changeset baseline and gate semantics, and the
[0.6 migration guide](../knowledge/reference/migrations/0.6.0.md) when upgrading older
configuration or automation. No dependency acquisition, lock acceptance, or content migration
is triggered by selection.

## Resolve selection before reading content

```sh
okf bundle select knowledge --json
# Save the bundle-selection record's token string verbatim to selection.json.
okf show concepts/selection-and-scope --selection @selection.json --json
okf changeset recover --selection @selection.json --json
```

`bundle select` emits a `bundle-selection` record with canonical root, identity, source
kind, effective access, and a versioned token. It resolves metadata without bundle
contents, guidance loading, or publication read guards. A pending transaction therefore
does not prevent selection. Check actual exit status and the complete operation stream
before using its receipt.

Global `--selection TOKEN|@file` reuses that current selection on supported bundle commands.
Explicit selectors must agree; historical revision selectors cannot be combined with it.
`init` and `bundle select` do not consume selection tokens. A token retains its original
catalog/access context instead of reselecting from a later working directory.

The receipt checks selection/configuration/catalog/override/lock dependencies, root identity,
and effective access. Native writers revalidate it while holding the writer guard. A managed
Git override remains read-only through its consumer catalog; an independently selected owner
checkout has its own access context. A selection receipt is a freshness assertion, not
authorization, guidance-delivery evidence, or a bundle-content snapshot. External filesystem
and catalog writers do not participate in bundle locking; these checks cannot eliminate all
races with them.

## Recover before loading normal context

Recovery skips guidance and rejects `--context` and explicit `--guidance full|summary`;
`--guidance off` remains accepted. Context tokens depend on ordinary bundle reads and cannot
bootstrap recovery. Resolve selection, recover the pending transaction, then reload applicable
context before content work. Direct path-based recovery remains supported.

Recovery retains guarded rollback/committed-cleanup behavior and refuses intervening-edit
conflicts. Preserve a conflicted journal. No pending transaction does not prove an earlier
write never committed; reconcile the expected post-state before retrying an append.

## Logical changeset preflight

The 0.6.5 scoped ontology gate understood `okf://` typed targets, but CLI changeset preflight
could still reject a valid logical reference before the gate ran. Version 0.6.6 corrects this
end-to-end path: explicit read scope resolves logical concept and artifact targets for
preflight, while ontology checks still enforce registered bundle identity and target type.

Use the same `--scope-bundle ID` or `--catalog-scope` for plan, digest, and apply. Registration
alone does not authorize examination; missing, unavailable, or out-of-scope dependencies
remain failures. Cross-bundle scope adds read dependencies and never authorizes target writes.
The existing guarded baseline and single-bundle journaled publication contract remains.

## Distribution

Release assets use the established macOS/Linux ARM64 and x86_64 workflow, `SHA256SUMS`, and
standalone installer. Official binaries include `url-sources`; macOS signing/notarization
follows the existing release process. Preparing this checkout does not publish release assets.
