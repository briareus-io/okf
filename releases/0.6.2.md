# OKF CLI and plugin 0.6.2

OKF 0.6.2 adds configurable readable YAML and an explicit presentation formatter for concepts
and bundles. Markdown prose wrapping is opt-in. Formatting preserves parsed frontmatter values,
verification events, and generation metadata; meaningful edits retain their existing review rules.

## Upgrade and compatibility

- The core document specification remains OKF v0.2. No bundle migration is required.
- Install matching CLI and plugin versions. The 0.6.2 plugin requires stable CLI versions
  `>=0.6.2, <0.7.0` because its instructions use `okf format`. Earlier CLIs fail its compatibility
  preflight. The workspace, lockfile, and both plugin manifests are versioned 0.6.2.
- Normal concept writes now use readable YAML by default. Existing files are not rewritten merely
  by upgrading or reading them. To retain previous serialization on subsequent writes, configure
  `settings.formatting.yaml.style: legacy` in `okf-bundle.yaml`.
- For upgrades across earlier releases, retain the
  [0.6 migration guide](https://github.com/briareus-io/okf/blob/v0.6.2/knowledge/reference/migrations/0.6.0.md)
  and [0.6.1 release notes](https://github.com/briareus-io/okf/blob/v0.6.1/releases/0.6.1.md).

## Explicit formatting

```sh
okf format notes/example --bundle knowledge --dry-run
okf format notes/example --bundle knowledge
okf format --bundle knowledge --check
okf format --bundle knowledge
```

The positional argument is an optional concept ID; the directory selector is `--bundle <path>`.
Omit the ID for the whole selected bundle. Registered `--bundle-id` selection is also supported.
`--dry-run` previews the complete diff without publishing. `--check` reports drift and exits 1
when formatting is needed, or 0 when clean; these modes are mutually exclusive. Ordinary runs
prepare changes before guarded, journaled publication. Tooling support files and opaque artifacts
are excluded. Checks/previews may create coordination state but do not publish authored content.

JSON emits `format-file` and `format-summary` records plus the standard operation envelope.
Schema metadata classifies formatting as a conditional mutation: both `check` and `dry-run` must
be false to apply. Documentation generation handles its named bundle selector explicitly.

## Presentation settings

Default policy in the bundle manifest:

```yaml
manifest_version: 1
settings:
  formatting:
    yaml:
      style: readable
      line_width: 100
    markdown:
      wrap_prose: false
      line_width: 100
```

A width of `0` disables wrapping for that format. Width counts Unicode characters and is a target,
not a hard limit: indivisible tokens can exceed it. Legacy TOML accepts the equivalent
`bundle_settings.<bundle>.formatting` tables, with the existing manifest/TOML conflict rules.
Bundle context exposes effective values and their origins.

Readable YAML folds eligible long single-line strings using `>-`, preserves actual multiline
values, and retains required quoting and escaping. The serializer parses its output and compares
values before accepting readable output, falling back to legacy rendering if they differ.
JSON and YAML inputs follow the same policy. YAML comments and authored scalar styles remain
outside the existing semantic serializer's preservation guarantees.

## Conservative Markdown wrapping

Markdown wrapping runs only through explicit `format`, even when `wrap_prose` is enabled.
Normal edits do not reflow bodies. The initial supported subset is ordinary top-level text
paragraphs. Lists, blockquotes, headings, code blocks, tables, HTML, reference definitions, and
paragraphs containing inline markup or unfamiliar syntax remain unchanged. Bodies containing
block markers `:::`, `!!!`, `???`, `+++`, `%`, or `{%` are skipped entirely.

URLs remain indivisible. Hard breaks, significant whitespace, paragraph-local line endings, and
missing final newlines are retained. Internally mixed-ending paragraphs are skipped. A parsed-event
comparison rejects changes to structure or text apart from soft line breaks. Formatting is
idempotent; this is not a general pretty-printer or support guarantee for every Markdown dialect.

## Documentation, skills, and evidence

The knowledge bundle now owns the
[format command reference](https://github.com/briareus-io/okf/blob/v0.6.2/knowledge/commands/format.md),
configuration guidance, navigation, and machine contracts. Shared plugin instructions and the
update/repair skills explain explicit formatting, opt-in policy, and preservation boundaries.
Generated CLI references are synchronized; the README remains a lean entry point.

Formatting retains verification metadata but does not verify claims, repair malformed YAML, or
refresh fingerprints. Raw file fingerprints can change; review citing sources before a separate
refresh. There is no new formatting lint rule: use `format --check` when a presentation gate is
wanted. Ontology field ordering remains the existing `frontmatter-order` lint's responsibility.

A fresh independent verifier found and rechecked fixes for unsupported directive reflow and
mixed-document newline handling. Regression coverage includes YAML value round trips, idempotence,
legacy and disabled wrapping, Markdown structure guards, directive exclusions, local newline
conventions, opt-in behavior, check/preview publication, verification retention, and schema metadata.
Independent CLI probes also checked atomic refusal and symlink containment.

Release validation covers workspace tests with default and URL-source features, skill workflows,
generated documentation, live manual examples, distribution/signing tests, and Rust formatting.
The publishing workflow builds and tests macOS and Linux on ARM64 and x86_64, signs and notarizes
both macOS binaries, and publishes four archives, checksums, and the standalone installer only
after the complete platform matrix succeeds. URL fingerprint refresh remains unwired to the CLI
network client; the release does not change that existing limitation.
