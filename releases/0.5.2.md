# OKF CLI and plugin 0.5.2

This patch release fixes false footnote attribution warnings in `okf lint` and
`okf doctor` ([issue #6](https://github.com/abatyuk/okf/issues/6)). The OKF
document specification remains v0.2. No commands, flags, or machine output
formats change. The plugin continues to accept stable CLI versions
`>=0.5.0, <0.6.0`.

## Footnote attribution

The optional `okf-v02` lint rule previously searched the raw Markdown body for
every `[^label]` sequence. Regex character classes such as `[^/]` in code spans,
fenced code, or plain prose were reported as footnotes without a matching
`sources[].id`. A real footnote with a definition could produce two warnings:
one for the reference and one for the definition. Since `doctor` includes this
lint rule, these warnings could make its summary report `ready=false`.

The rule now reads Markdown footnote references and definitions. It checks a
label against `sources[].id` only when the body contains both a reference and
a Markdown definition. Code spans and code blocks are ignored. An unresolved
label produces one warning even if the body refers to it several times.

For claim attribution, write a Markdown footnote definition and give the
corresponding source entry the same `id`:

```markdown
---
type: Note
sources:
  - id: evidence
    resource: https://example.org/evidence
---
Claim backed by this source.[^evidence]

[^evidence]: Evidence for the claim.
```

References without definitions no longer trigger this source attribution
warning. If you used an undefined `[^label]` marker to attribute a claim, add
its definition so the rule can check it. Defined footnotes without a matching
source ID still receive a warning. Existing `spec_v02` severity settings and
other lint rules are unchanged.

## Updating and distribution

Install CLI and plugin 0.5.2 together. Users upgrading from 0.4.x should read
the [0.5.0 migration guide](https://github.com/abatyuk/okf/blob/v0.5.2/knowledge/reference/migrations/0.5.0.md)
before updating. The [installation guide](https://github.com/abatyuk/okf/blob/v0.5.2/knowledge/getting-started/installation.md)
has archive and installer instructions. The standalone installer now points to
the current location of the migration guide.

Release CI tests the workspace with and without `url-sources`, checks generated
CLI references and the knowledge bundle, then builds all four native targets:
macOS Apple Silicon and Intel, and Linux ARM64 and x86_64 with musl. macOS
binaries are Developer ID signed and notarized. The published release includes
the archives, `SHA256SUMS`, and `install.sh`. macOS deployment target remains
13.0; Git-based operations require Git on PATH. Official binaries include
`url-sources`, while URL fingerprint refresh remains unwired to the CLI network
client.
