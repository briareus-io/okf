# OKF CLI and plugin 0.6.1

OKF 0.6.1 fixes source-path inconsistencies and lost-reference diagnostics, coordinates CLI readers
with bundle publication, and makes source replacement and verification invalidation more explicit.
It adds absence-aware filters, ontology field descriptions, opt-in body-link normalization, and a
worked operational-bundle recipe. Changeset preparation also reuses unchanged parsed documents.

## Upgrade and compatibility

- Install matching CLI and plugin versions. The 0.6.1 plugin requires stable CLI versions
  `>=0.6.1, <0.7.0`, because its guidance uses the new predicates and normalization flag. CLI 0.6.0
  is no longer accepted by this plugin's preflight. The workspace and both plugin manifests are 0.6.1.
- The core document format remains OKF v0.2. Manifest v1, catalog v2, and lock v1 are unchanged.
- Keep the [0.6 migration guide](https://github.com/briareus-io/okf/blob/v0.6.1/knowledge/reference/migrations/0.6.0.md)
  for configuration/profile changes when upgrading from an earlier minor release. The corrections
  below also matter when upgrading directly from 0.6.0.
- Automation must accept an explicit busy/pending-recovery error from coordinated working-tree
  reads, interpret new diagnostic and normalization records, and continue checking the actual
  process exit and terminal operation evidence. `consistency: working-tree` is not a snapshot claim.

## Source paths and cross-bundle diagnostics

- Doctor now retains typed-source semantics: `file`, `line-range`, and `markdown-heading` resources
  resolve relative to the bundle root, consistently with fingerprinting and graph resolution.
  Kind-less provenance and ordinary body links retain document-relative semantics. A leading `/`
  in a typed file source retains filesystem-absolute meaning; it is not the bundle-root prefix
  used in Markdown links.
- **Correct typed sources that relied on the old graph interpretation.** For a concept at
  `a/notes/n.md`, a typed file source in sibling bundle `b` is anchored from bundle `a`, not from
  `a/notes`. Its relative spelling is `../b/...`, rather than `../../b/...`. Registered target
  identity and explicit scope still govern cross-bundle graph examination; changing the spelling
  does not grant permission or waive containment checks.
- Doctor accepts explicit `--scope-bundle` and `--catalog-scope` and resolves scoped cross-bundle
  sources, including logical references and `bundle_ref` identity/snapshot expectations. Missing,
  unavailable, out-of-scope, blocked, and mismatched evidence remain distinct findings.
- Generic artifact resolution and reads now support ordinary cross-bundle paths to explicitly
  scoped registered targets, alongside existing `okf://` support. These commands cannot infer a
  source kind from a string: `--from` remains document-relative; omit it for typed bundle-root
  source resources. A leading `/` in the generic artifact interface remains bundle-root-relative.
- New `qualified-cli-target` diagnostics catch recognized registered-bundle CLI targets such as
  `demo.b:/specs/x.md` in authored body links, sources, and declared reference fields. Use ordinary
  paths or `okf://demo.b/specs/x.md` instead. The diagnostic uses `settings.lint.invalid_reference`,
  default `warn`; arbitrary external URI schemes are not reinterpreted as concept references.
- Changeset reference validation now resolves a suffix-free concept ID when a same-stem directory
  also exists. `/milestones/M1` can name `milestones/M1.md` beside `milestones/M1/`; directory-only
  and escaping targets remain invalid.

## Readers and publication

Ordinary working-tree CLI reads and checks hold shared publication guards across the selected
available bundle roots, acquired in a deterministic order and retained through payload delivery.
An active cooperating publisher or pending recovery journal produces an explicit nonzero refusal
before payload delivery. This prevents a successful inventory from observing part of a cooperating
changeset publication. Read-only checks are covered; commands that repair or publish retain their
own mutation coordination.

Publication remains journaled and atomic per file. Arbitrary filesystem readers can still see
intermediate states, and editors or tools that bypass the locks can change files during a CLI read.
Separate CLI invocations are not one snapshot. Managed immutable snapshots need no coordination
writes. A read-only root without an existing lock remains readable without a coordination guarantee
against privileged or external writers. NDJSON therefore continues to report `working-tree`, not
an immutable snapshot.

Use `changeset recover` after interrupted publication; do not remove the journal manually.
Application read-compute-write operations still need a baseline captured before their decision and
passed to `changeset apply --expect`. A fresh baseline obtained after a stale decision cannot guard
that decision. Harness-specific locks remain useful for coordinating several related commands.

## Source edits and review evidence

- An edit that both adds a source and removes a selector matching that addition is rejected before
  writing. It no longer succeeds with the replacement source silently removed. Argument order does
  not define source replacement semantics.
- Replace a source in one guarded JSON Patch instead of removing and re-adding it in separate
  edits. Test the expected source object, then replace the required property or object; this
  preserves unrelated metadata and avoids an intermediate source-less document.
- Plain applied and dry-run edit output now explicitly reports verification invalidation. JSON
  retains its structured invalidation evidence. Meaningful edits invalidate active verification;
  no-op edits preserve it.
- `verification_current` remains a nullable timestamp comparison: latest valid verification versus
  the effective generation timestamp. `null` can mean no generation timestamp is available, even
  for a reviewed concept. `trust_tier` identifies review evidence but does not alone establish its
  currency. Documentation now spells out this distinction rather than forcing a misleading true/false.

There is no unrestricted `--keep-verified` escape hatch. Repointing a source or changing metadata
can change meaning or evidence identity. Preserve historical review evidence in version history
or an audit trail and arrange re-review when needed.

## Explicit body-link normalization

`okf doctor BUNDLE --normalize-relative-links` previews mappings and diffs for bare body links to
their checked current document-relative targets. Add `--yes` to publish; `--dry-run` always previews.
JSON exposes `doctor-normalization` records. This is an explicit choice of current semantics, not
an inference about the original author's intent and not an expansion of default `--fix-safe`.

Only destination bytes change. Frontmatter and sources, labels, titles, query/fragment suffixes,
and surrounding Markdown remain intact. Missing or blocked targets and unrecognized or ambiguous
destination syntax remain for review. If normalization and safe repair are requested together,
normalization publishes first and safe repairs use a separate transaction; they are not one atomic
operation. Inspect completion/publication evidence if a later step fails.

## Queries, ontology, and machine-consumer guidance

- Metadata filters add `!=`, `exists`, `absent`, `is null`, and `is not null`. Top-level uppercase
  `OR` combines alternatives within a filter; repeated filters remain AND. JSON strings/arrays
  containing `OR` are not split. For example:

  ```sh
  okf search knowledge --facet-filter 'impl_status not in ["implemented"] OR impl_status absent' --full-scan --json
  ```

- Existing `not in` semantics are unchanged: absent/null values do not match; `!=` also excludes
  them. Presence includes selected empty lists. Null predicates are existential over occurrences,
  so a mixed list can satisfy both through different elements; a selected empty list also satisfies
  `is not null`. These predicates do not introduce correlated same-record querying.
- Field and reusable field-type declarations recognize `description` as non-enforcing metadata.
  Descriptions survive resolution/inheritance/export and display without per-concept unsupported-
  constraint warnings. Unknown enforcing constraints still receive diagnostics.
- The existing identity contract is now explicit: unprojected `id` is the computed path and
  `frontmatter_conflicts.id` retains an authored ID. `--project '$id' --project id` selects them
  separately in projection records. The default row layout has not changed.
- Machine consumers can use central `--guidance off` or manifest `guidance.display.json: off`.
  Agents still load applicable context before acting. Consumers must require supported start and
  terminal completion records, not merely validate a trailer if one happens to be present.
- The plugin includes a complete Task/Defect/Milestone example: stable authored IDs, typed
  dependencies, complete inventories, guarded batches, ordering, and recovery without routine
  fingerprints. Application readiness, ID allocation, cycle detection, and state-transition policy
  remain owned by the consuming harness.

## Changeset performance and ordering

Preparation reuses parsed unchanged documents within one invocation. Full baseline conflict checks,
final reference checks, and isolated staging remain; this is not a persistent index or an
incremental-validation guarantee. Eight alternating release-binary runs per version on synthetic
single-create planning fixtures measured:

| Concepts | Before | After | Approximate reduction |
| --- | --- | --- | --- |
| 100 | 122.6 ms | 113.0 ms | 8% |
| 665 | 447.7 ms | 361.0 ms | 19% |
| 2,000 | 1,062.6 ms | 879.8 ms | 17% |

These local measurements ran with other validation work active; they are directional evidence,
not a latency promise. Bundle shape, artifacts, filesystem, and operation mix affect costs.

Documentation now gives a concrete ordering example: edit an old-path link before moving its
target and the move can rewrite it; write that old link after the move and final validation rejects
the introduced dangling reference. `apply` already prepares and validates in one invocation; no
`--expect-current` flag is added as a substitute for a reviewed baseline.

## Remaining boundaries

- Cross-bundle move retargeting and multi-bundle atomic changesets are not implemented. Scoped
  moves keep integrity guards; external consumers need explicit reconciliation and recovery policy.
- Pagination still rescans. There is no persistent index, snapshot-bound query cache, or shared
  result handle. Use one complete inventory for application-wide analysis.
- Changesets still stage a whole bundle and perform whole-baseline checks. The parsing optimization
  does not remove that cost or weaken validation.
- Normalization does not automatically recover historical author intent. Verification invalidation
  is not removed, and timestamp currentness is not replaced by verification presence.
- Harness stream decoders, application locks spanning multiple commands, and domain-specific
  readiness/identity policies remain consumer responsibilities. This release does not edit external
  harnesses or their generated instructions.

Release assets are built by the release workflow for macOS and Linux on ARM64 and x86_64, with
`SHA256SUMS` and the standalone installer. macOS artifacts follow the established signing and
notarization workflow. Local metadata preparation alone does not publish these assets.
