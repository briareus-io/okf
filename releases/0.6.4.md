# OKF CLI and plugin 0.6.4

OKF 0.6.4 is a maintenance release. It fixes link rewriting in `okf mv`, byte-order-mark handling,
and process exit behaviour when output is piped or cannot be written. It also hardens file writes,
migration rollback, symlink checks and Git subprocess handling. The CLI contract is unchanged:
commands, arguments, NDJSON records, `okf schema --json` and exit classes for valid input are the
same as in 0.6.3.

## Upgrade and compatibility

- There are no CLI contract changes. The 0.6.4 plugin keeps the supported stable CLI range
  `>=0.6.3, <0.7.0`, so CLI 0.6.3 remains accepted. The workspace and both plugin manifests are
  0.6.4. The OKF document format remains v0.2. Manifest v1, catalog v2 and lock v1 are unchanged.
- Small observable fixes:
  - **`okf mv` links:** inbound links written with percent-encoding (`a%20b.md`), entity references
    (`a&amp;b.md`), or a destination shared by several links are now rewritten. 0.6.3 left them
    pointing at the old path.
  - **Pipe exit status:** when a downstream reader closes the pipe early, for example
    `okf list | head`, okf now stops quietly and exits 0. 0.6.3 was terminated by `SIGPIPE`
    (shell status 141).
  - **Output ordering:** buffered standard output is flushed before an error message, so partial
    output appears before the `okf: …` line on a terminal. Human-readable output now goes through
    the same buffered writer as NDJSON.
  - **I/O exit class:** a failed write of JSON output to standard output is reported as an I/O
    failure (exit 3) rather than an internal error (exit 4).
  - **Byte-order mark:** a concept that starts with a UTF-8 BOM is now recognised as having
    frontmatter. 0.6.3 reported it as `missing-frontmatter`. `format` and `format --check` now
    cover its frontmatter as well, and `format` and `mv` keep the BOM when they rewrite the file.
- Source builds now use Rust edition 2024 and declare `rust-version = "1.98"`. The pinned
  toolchain in `rust-toolchain.toml` is unchanged. Release binaries are built with thin LTO, one
  codegen unit and stripped symbols.

## Fixes

- `okf mv` link rewriting computes the correct relative file segment and edits each destination
  span once when several links share it. It matches percent-encoded and entity-encoded
  destinations the same way the Markdown parser reads them. Unknown entities are left unchanged.
- Fenced code blocks are tracked per CommonMark, matching the fence character and length.
  Section-aware body edits no longer treat a `~~~` line as the end of a block opened with a
  backtick fence, or a shorter fence as the end of a longer one.
- A Git child that exits before reading its input no longer terminates okf through `SIGPIPE`.

## Robustness and hardening

- Every durable write follows one protocol: create an exclusive temporary sibling, write and sync
  it, keep the destination's permissions, publish it and sync the parent directory. The temporary
  file is removed on every exit path. Lock guards are `#[must_use]`, so a guard cannot be dropped by accident.
- Migration writes and rollback are atomic. A failed rollback keeps the original error.
- `load_concept` rejects symlinked path components, as the bundle walker already did, so a
  symlinked directory cannot redirect a read outside the bundle. On Unix, manifest, instruction,
  workflow and bundle resource reads check that the opened file is the one that was validated.
- Git subprocesses are owned by kill-on-drop guards and reaped on early return. A failed
  `cat-file --batch` read discards the cached reader instead of reusing a stream that may be
  mid-object. Batch responses are checked for correct framing. Names that the batch protocol
  cannot carry fall back to `git show`.
- `catalog update` validates the identities in the previous lock (URLs, commit IDs, object format
  and paths) before passing them to Git. Uppercase hexadecimal commit IDs in a lock are
  normalised to lowercase, so they compare equal to Git's output.
- Ontology `pattern` regexes are compiled once per pattern and cached.
- Production `unwrap` calls in the CLI, the core library and `xtask` were replaced with checked
  errors. An invalid UTF-8 file in a changeset still fails with exit 3; the message now says so.

## Internal changes

- `OkfError` keeps the underlying `io::Error` source. Write-gate, baseline-conflict and
  context-invalid failures carry a typed `FailureReason` instead of being classified by message
  prefix. Messages, exit codes and JSON failure reasons are unchanged.
- `Edge.status` is now an `EdgeStatus` enum, the `default_bundle` selector is an id/path enum,
  and `--format`/`--fail-on` (including `refresh --fail-on`) are parsed with clap `ValueEnum`.
  Accepted values, defaults, help text and schema output are unchanged.
- The workspace declares shared dependencies and lints: `rust_2018_idioms` and a selection of
  pedantic Clippy lints. A blanket `dead_code`/`unused` allow and the dead code it hid were
  removed. The code was reformatted with the 2024 style edition.
- Tests share the okf command helper. The test HTTP server reads requests up to the header
  terminator.

Release assets are built by the release workflow for macOS and Linux on ARM64 and x86_64, with
`SHA256SUMS` and the standalone installer. macOS artifacts follow the established signing and
notarization workflow. Local metadata preparation alone does not publish these assets.
