# OKF 0.5.0

**BREAKING CHANGE:** This minor release changes CLI input handling, NDJSON
operation streams, source-health diagnostics, and write semantics. Read the
[migration guide](https://github.com/abatyuk/okf/blob/v0.5.0/docs/0.5.0-migration.md) before installing over 0.4.x.
The CLI and both agent plugins are version 0.5.0. The OKF document
specification remains v0.2; conformant bundles need no format migration.

## Command and output changes

- Explicit `affected --changed` arguments no longer consume an unrelated
  inherited stdin pipe. Add `--changed -` to include stdin deliberately.
  `--changed-base bundle|repo|filesystem` identifies the namespace used for
  changed resources; bundle interpretation remains the default.
- Ineffective argument combinations now fail as usage errors: `affected
  --depth` without `--transitive`, `computation check --details`, and `init
  --title` with `--no-index`. Existing `--fail-on info|warn|error` discovery
  aliases remain available with a deprecation diagnostic.
- JSON operations use versioned `operation-start` and `operation-complete`
  records around their existing payloads. Completion reports outcome,
  publication evidence, and applicable read completeness. Consumers must
  recognize the terminal record and actual exit code; an interrupted stream
  can lack completion. Schema describes command effects and record versions.
- Source observations distinguish unrecorded, missing, unavailable,
  unsupported, drifted, expired, and provenance-only cases. `stale` display
  filtering and state-based failure policy are separate controls.

## Writes and coordination

- A single refresh prepares required fingerprints before publication; failure
  of a required source leaves the concept unchanged. Kindless provenance does
  not request a fingerprint. Refresh neither verifies knowledge nor changes
  standard source timestamps or expiry.
- Content-read-only `changeset digest` exposes the guarded baseline used by plans
  without requiring a dummy operation document. Plans and digests can create
  coordination files; ordinary reads remain filesystem read only.
- CLI authored writers use the journaled publisher and guarded recovery. A
  publication interruption can require `changeset recover`; no output trailer
  alone is not rollback evidence. `lint --fix` is confined to one selected
  bundle per invocation. Read-only lint still supports catalog scope.
- Optional ontology write gates compare the prospective state and are
  independent of lint severity/display settings. A CLI request cannot weaken
  the configured minimum. Shared sidecar changes require explicit dependent
  scope where applicable. Structured changeset creation and narrow deletion
  override extend the existing changeset input contract.

The write gate reports `write-gate-incomplete` and blocks a write when a typed
reference points outside the examined bundle and its target cannot be checked.
Explicit dependent ontology examination checks the named bundles' concepts;
it does not expand ordinary reference traversal across those bundles. There
is no 0.5 CLI override for an incomplete gate.

The public low-level `save_ontology(path, …)` library API writes directly;
CLI ontology commands use the journaled path. Library callers needing the
same recovery guarantees must use the guarded publication API.

## Compatibility and limits

The 0.5.0 plugins require a stable CLI `>=0.5.0, <0.6.0`. The prior 0.4.4
plugins support `>=0.4.4, <0.5.0`; update the plugin and binary together.
Automations that parse NDJSON or depend on 0.4.x warning behavior need the
changes in the [migration guide](https://github.com/abatyuk/okf/blob/v0.5.0/docs/0.5.0-migration.md). The previous
release can remain pinned during migration. There is no global legacy mode.
Source installation through `cargo xtask install` uses the checked-in
`Cargo.lock` dependency set.

This release does not include batch refresh, batch link resolution,
map-value selectors, materialized results, general immutable
snapshot, cross-bundle transaction, or export pipeline. Check `okf schema`
for supported command forms. Runtime network access remains limited to
explicit URL artifact retrieval where built with `url-sources`; local
operations do not require a service.

## Validation and platforms

Before publication, the release gate runs workspace tests, URL-source tests,
generated-reference checks, distribution tests, and skill workflow checks.
The 0.5.0 regressions cover command conflicts, explicit stdin, stream
completion, source states, write gates, transaction recovery, and scope.
See [consistent command behavior](https://github.com/abatyuk/okf/blob/v0.5.0/docs/consistent-command-contracts.md),
[checking results and recovering writes](https://github.com/abatyuk/okf/blob/v0.5.0/docs/command-contracts-validation.md),
and [performance and bounded reads](https://github.com/abatyuk/okf/blob/v0.5.0/docs/command-performance.md) for usage and limits.
GitHub Actions builds macOS
(Apple Silicon and Intel) and Linux (ARM64 and x86_64 musl). macOS published
binaries require Developer ID signing and notarization. Windows binaries are
not provided. An installer verifies the archive checksum and executable
before replacing its destination and emits the breaking-change notice first.
