# OKF CLI and plugin 0.5.1

This patch release fixes false broken-link lint findings and consolidates the repository's
documentation into a single, usable OKF knowledge bundle. No commands, flags, or output
formats are added or removed. The OKF document specification remains v0.2; the plugin
continues to accept stable CLI versions `>=0.5.0, <0.6.0`.

If upgrading from 0.4.x, first review the
[0.5.0 migration guide](https://github.com/abatyuk/okf/blob/v0.5.1/knowledge/reference/migrations/0.5.0.md).

## CLI fix

`okf lint` previously reported links to existing `index.md` navigation pages and opaque
artifacts such as YAML/JSON examples as missing concepts. It now resolves the original
link spelling and accepts existing reserved files and artifacts inside the bundle.
Missing targets and artifact symlinks escaping the bundle still produce findings.
Regression tests cover navigation, artifacts, missing targets, and blocked symlinks.

This can turn a failing lint result into a clean result for bundles whose only errors were
those false positives. It does not change concept conformance, permit access outside the
bundle, or disable the broken-link rule.

## One documentation bundle

The [knowledge bundle](https://github.com/abatyuk/okf/blob/v0.5.1/knowledge/index.md) now serves
both users and contributors. The README is a short entrance with installation, a working
quickstart, and navigation. The separate `docs/` directory is removed.

- Task guides cover retrieval, modeling, source-backed maintenance, reorganization,
  multiple bundles, bounded reads, and JSON automation.
- Concepts and shared reference explain provenance, verification, relationships,
  scope, configuration, selectors, and command contracts.
- All 48 command pages retain their IDs and own their generated argument tables,
  supported globals, and focused usage notes. Shared global arguments and record
  contracts have one generated reference. Plugin workflows retain their portable,
  generated CLI subsets.
- Contributor architecture, detailed capability designs, validation reports, and release
  instructions live in the same bundle. Twelve decisions are rationalized into nine.
  Historical architecture and intent drafts are removed in favor of current guidance.
- The Rust type catalogue is removed; implementation types belong in Rust API documentation.
  Component pages are consolidated into an implementation module map.
- A source-to-destination ledger preserves the documentation migration mapping, and
  source references point to current repository files. Recorded fingerprints and Git blob
  provenance links are removed; migration does not create verification events.

Old repository documentation paths and decision IDs have moved. Use the
[migration ledger](https://github.com/abatyuk/okf/blob/v0.5.1/knowledge/contributing/validation/documentation-consolidation.md)
to update bookmarks or links. Version-pinned references to older releases remain valid.

## Working examples and maintenance

The [live tour](https://github.com/abatyuk/okf/blob/v0.5.1/knowledge/guides/tour-the-bundle.md)
queries the manual's real metadata, views, relationships, backlinks, expansion, and source
impact. Three small artifacts demonstrate a coordinated changeset, an ontology definition,
and a guarded metadata patch, using disposable tutorial bundles. Expanded guides also
provide a complete local catalog setup, a JSON consumer with completeness checks,
relationship authoring, bounded-read examples, and maintenance without fingerprints.

`cargo xtask docs` now synchronizes command group/write-capability metadata and fails when
a command page is missing. `scripts/check-docs.py` checks navigation, command coverage,
bundle lint, live showcase queries, and the published examples; it runs in CI.

The repository's `okf.toml` disables only `source_unrecorded` lint findings. Other lint
findings still fail the documentation check. This is local bundle configuration, not a
change to the CLI's default lint policy. Source-missing checks remain active. Without recorded
fingerprints, drift cannot be established for this manual; use known source changes with affected analysis and review.

## Validation and distribution

Release validation includes the workspace test suites with and without `url-sources`,
skill scenarios, generated-reference checks, Python release-tool tests, documentation
checks, and formatting checks. The publishing workflow tests and builds all four native
targets before publishing archives, `SHA256SUMS`, and `install.sh`.

Official targets are macOS Apple Silicon and Intel, and Linux ARM64 and x86_64 with musl.
macOS release binaries retain Developer ID signing and Apple notarization. The macOS
deployment target is 13.0; older OS behavior is not newly certified by this release.
Archives and standalone executables cannot carry a stapled ticket, so Gatekeeper may
need internet access. Official binaries include `url-sources`; Git-based operations
require Git on PATH. URL fingerprint refresh remains unwired to the CLI network client.
