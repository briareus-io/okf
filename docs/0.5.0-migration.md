# Migrating to OKF CLI 0.5.0

**BREAKING CHANGE:** CLI 0.5.0 changes command input, JSON streams, source
diagnostics, and write behavior. Update the CLI and the OKF agent plugin together.
The 0.5.0 plugin requires a stable CLI `>=0.5.0, <0.6.0`; the 0.4.4 plugin
requires `>=0.4.4, <0.5.0`. The OKF document specification remains v0.2, so
existing conformant Markdown concepts need no format conversion.

## Before upgrading

1. Pin any program that parses `--json` output to the 0.4.x binary until it
   recognizes the 0.5.0 stream contract. Use `okf version` to check the binary
   that actually resolves on `PATH`.
2. Review scripts that pipe changed paths, run scoped `lint --fix`, refresh
   fingerprints, or depend on an ignored flag. Use the replacements below.
3. Review [the 0.5.0 release notes](../releases/0.5.0.md) and the generated
   [CLI reference](okf-cli-reference.md) for exact flags and record shapes.
4. After updating the binary and plugin, run the plugin's read-only compatibility
   check and exercise automation against a copy of a representative bundle.

## Invocation changes

| 0.4.x behavior | 0.5.0 invocation or action |
| --- | --- |
| `printf '%s\n' path.md \| okf affected bundle --changed other.md` implicitly combined the pipe with the argument | Pass `--changed -` to read the pipe explicitly: `printf '%s\n' path.md \| okf affected bundle --changed other.md --changed -`. An invocation with complete explicit input does not read unrelated stdin. |
| `okf affected bundle --depth 2` warned or had no effect | Add `--transitive --depth 2`, or remove `--depth`. |
| `okf computation check id bundle --details` warned or had no effect | Remove `--details`. |
| `okf init bundle --title X --no-index` accepted an ineffective title | Remove `--title` or create the index. |
| `okf lint bundle --fix --scope-bundle other` could fix several bundles | Run `okf lint --fix` separately for each explicit bundle. Each invocation is its own transaction. Read-only scoped lint remains available. |
| Changed Git paths were interpreted in the bundle namespace | Select the namespace with `--changed-base repo` for paths relative to the repository worktree, or `--changed-base filesystem` for filesystem paths. The default remains bundle-relative. |

Only one input argument may consume stdin. An empty explicit ID file means an empty
selection, not every concept. Batch mutation requires an explicit selector or `--all`
when that command supports batch selection; output pagination does not limit writes.

## JSON consumers

Under `--json`, an operation normally starts with `operation-start`, keeps its
command-specific payload records, and ends with `operation-complete`. The trailer
reports `outcome`, `exit_code`, publication state, completeness dimensions, and
reason codes. Existing query summaries remain payload records. Parse the stream
as NDJSON, check its declared stream version, require the terminal record, and
compare its declared exit with the actual process exit. EOF without a trailer is
not proof of a successful read or rollback. Argument parsing can fail before
the start record, and interruption can prevent completion output.

A successful process exit can still accompany a partial bounded read. Inspect
`completeness.examination` and `completeness.matching` before treating zero matches,
counts, or ordering as exhaustive. Treat `outcome` as an operation result; it is
never an authored concept `status`. Existing concept lifecycle meanings remain
`draft`, `stable`, and `deprecated`, with absent status treated as stable.

Source-health readers must distinguish `drifted`, `unrecorded`, `missing`,
`unavailable`, `unsupported`, `expired`, and provenance-only observations.
For `stale`, `--only` filters displayed diagnostics and `--fail-on-state`
selects a failure policy independently. Read schema and the generated reference for the actual
record-family versions and supported command combinations; do not infer them
from human diagnostic text.

## Writes, baselines, and recovery

Single-concept refresh prepares required fingerprints before publishing. A
missing, unavailable, or unsupported required source blocks publication rather
than allowing unrelated fingerprints to update. Split independent work into
separate refresh calls after reviewing the source evidence. A kindless source is
provenance only and is not a fingerprint failure. Refresh does not verify a
concept or clear an expired `stale_after`.

`changeset digest` returns a guarded baseline without creating a dummy plan.
Plans, previews, and digest acquisition may create coordination state and need
the required filesystem permissions, while ordinary reads remain read only.
CLI authored writers use the journaled single-bundle publication protocol.
After an interrupted write, inspect its terminal publication evidence if present,
then use `okf changeset recover` when a pending journal exists. A missing trailer
alone cannot establish whether publication happened.

An ontology write gate is optional. When enabled, it is independent of lint
display and severity settings and cannot be weakened by a CLI flag. Shared
ontology edits require explicit dependent-bundle examination where applicable.
The gate blocks with `write-gate-incomplete` if an out-of-bundle typed target
cannot be checked. Explicit dependent-bundle examination does not silently
expand ordinary references into additional scope.
Changeset creation can use structured metadata inputs; conflicting complete
content and structured representations are rejected. The narrow
`allow_dangling` deletion override does not bypass an enabled ontology gate.

## Compatibility fallback

Pin CLI 0.4.4 and its matching plugin while adapting an integration. Keep a
separate 0.5.0 installation for trials and select it explicitly through `PATH`.
No global legacy mode is provided. Batch and map-selector extensions should
be used only if they appear in the 0.5.0 schema and generated reference.
